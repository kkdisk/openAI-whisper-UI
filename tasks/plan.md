# 實作計畫：本機離線會議逐字稿工具

> 建立日期：2026-11-06。狀態：v0.1.0 已提交；R01 長檔轉錄完成、品質驗收未完成。M6～M9 多數仍待實作；turbo CPU 選項已先加入。證據見 [validation.md](validation.md)。
> 需求依據：[SPEC.md](../SPEC.md)。執行清單：[todo.md](todo.md)。

## 1. 交付目標與規劃原則

交付 Windows 本機 Web UI：選取約 60 分鐘 MP4，使用 CPU INT8 的 faster-whisper 轉錄中文與英文術語，匯出帶時間戳 TXT、會議整理用 Markdown 與選用 SRT。

- 預設 small 多語言模型、中文、4 執行緒、VAD、保守 OpenCC s2t（僅替換簡體專用字）。
- 日常完全離線；模型準備與套件安裝是獨立步驟。
- 一次一個活動任務；保留歷史結果，使用者主動刪除前不覆蓋。
- 先完成短檔轉錄與匯出，再補齊子程序、串流上傳及 UI，最後驗證真實長檔。
- M0～M5 保留 v0.1.0 範圍；M6～M9 規劃文字品質、GPU、說話者分離及人工姓名對應，依 SPEC 第 13 節執行。雲端摘要、續傳／續算、VTT 與 EXE 打包仍不包含。
- SPEC 定義行為；本文件定義順序與交付條件；todo 記錄執行狀態。需求變動先同步 SPEC，避免三份文件各自演進。

## 2. 現況與外部輸入

規劃建立時只有規格與規劃文件，沒有應用程式、鎖檔、測試或模型。目前已備妥 Python 3.10.11、uv 0.12.5、鎖檔與本機 small 模型；實際驗證結果見 validation.md。

使用者已指定 temp 內的一份 108 分鐘 M4A 作長檔驗證；尚缺真實 MP4 與術語／型號人工參考清單。合成中文短語音已驗證 MP4 AAC 核心路徑，但不能代替真實會議品質接受。測試素材與逐字稿不納入版本控制，不上傳外部服務。

R01 現已 completed：5,087 段、約 57 分 37 秒，無執行錯誤；文字抽樣暴露疑似誤辨、重複與片段過碎。CPU 筆電仍為基準，RTX 2060／6 GB 為另一目標配置，不假設目前電腦已有 GPU。下一步先建立人工短樣本，模型準備授權、GPU 實機及姓名參考是各自驗收輸入，不讓缺少 GPU 阻止 CPU 說話者流程的評估。

## 4. 各階段實作內容

### M0：環境與共用契約

- 建立 pyproject.toml、dev 群組、uv.lock、app 套件、tests、.gitignore；排除模型、媒體、逐字稿、環境與暫存。
- 選擇實際支援 Python 3.10.11 的套件版本，驗證 CTranslate2／PyAV／onnxruntime Windows wheel 與必要執行期。先鎖定可用組合，不直接追隨最新版本。
- 定義設定、任務 metadata、片段、錯誤回應與 SSE payload；版本化本機資料格式。設定集中管理 SPEC 的大小、時長、逾時與取消參數。
- 初始定義測試標記：一般單元／API、Windows 程序、真實模型 opt-in；一般測試不需下載模型或接觸網路。

通過條件：已備妥環境可 import 核心依賴；相同鎖檔可重建；空模型目錄不引發下載。

### M1：模型準備、辨識與匯出

- 實作 prepare_models.py：白名單 repo、固定 revision、扁平 local_dir、準備中／可用狀態、模型來源紀錄；載入與 VAD 實測成功才標記可用。
- 模型管理只解析已知名稱到專案內絕對路徑；檢查必要資產與套件內 VAD，禁止以模型代號回退下載。
- transcriber.py 處理第一音軌、無音軌／損毀、120 分鐘限制、CPU INT8、zh／auto／en、200-token 完整提示限制及 VAD 原始時間映射。
- 清楚區分階段：明確解碼音訊後再將陣列交給辨識引擎，避免為檢查與轉錄解碼兩遍；保留取消控制及記憶體量測點。
- formatter.py 保存 raw_text 與 text；產生帶時間戳 TXT、原始 TXT、會議整理 MD、SRT，含 partial 標記及安全檔名。
- SRT 的非法時間錯誤只影響 SRT；TXT／MD 必須仍能保留內容，異常時間位置顯示明確標記而不是讓共用格式器整體崩潰。
- 先用短語音 fixture 建立端到端核心驗證，不以靜音產生空白結果當作辨識成功。

通過條件：禁止連網的短檔驗證通過；模型缺檔清楚失敗；中英文字、原始文字及三種匯出完整；仍不代表 60 分鐘品質驗收通過。

### M2：任務持久化與程序控制

- jobs.py 管理單一活動位置、狀態轉移及不可覆寫終態；由主程序唯一寫入 metadata／JSONL。
- metadata 採同磁碟暫存檔與原子替換；JSONL 逐筆保存後才通知。恢復時保留完整行，對中斷的最後一行明確處理與記錄，不丟棄前面片段。
- Windows spawn 子程序先等待 Job Object 綁定，綁定後才載入模型；主程序獨占 Job handle，未綁定期間監看父程序 sentinel。這部分集中在小型內部 helper，避免散落在路由。
- 每次任務獨立子程序與具背壓的 Pipe；強制終止後棄用該任務 IPC，避免損壞的管道被下一個任務重用。接收與 join 不得無限等待。
- 取消先協作等待 2 秒再終止，確認退出後清理；活動位置只在工作程序與上傳寫入都停止後釋放。
- 掃描歷史 metadata、啟動後標記 interrupted、清理工具內殘留媒體；支援分頁清單、latest、結果刪除及壞損項目提示。

通過條件：假工作程序驗證獨占、崩潰、取消競爭、持久化恢復與父程序強制退出；已保存片段可匯出。Windows 實際視窗關閉另列人工驗收，不用正常 shutdown 代替。

### M3：HTTP API、串流及 SSE

- main.py 以單一服務程序啟動，不使用多 worker 或日常 auto-reload，避免記憶體鎖／session／程序所有權分裂。
- POST /api/jobs 接收小型 JSON，模型／磁碟／參數預檢後原子保留位置並立即回傳 ID；tokenizer 最終檢查依 M1 在工作程序內執行。
- PUT media 在讀 body 前驗證 session、任務、狀態、類型；以原始串流單次寫入，處理超量、宣告不符、磁碟不足、斷線、重複 PUT、未開始／閒置／總上傳逾時及取消競爭。
- 完整接收且關閉媒體後啟動子程序；音軌驗證與推論錯誤由狀態／事件回報，不以 HTTP 202 當作轉錄成功。
- 實作 SPEC 全部查詢、匯出、取消與刪除端點；下載只能引用已驗證任務內的結果。
- SSE 使用短期通知，重連靠持久化快照及 after_id 補齊；先建立事件接收再取得快照／補查，依片段 ID 去重，涵蓋重連期間的競爭。
- loopback Host／Origin、單一記憶體 session cookie、CSRF header 與靜態頁面引導流程一併完成；錯誤回應不洩漏內容或路徑。

通過條件：模擬轉錄 API 全流程通過；早期拒絕不主動讀取媒體；歷史可回查；SSE 斷線不停止工作，重連不漏字或重複。

### M4：使用者介面與日常啟動

- 本機 HTML／CSS／JS：會議資訊、選檔／拖放、模型狀態、詞彙提示、語言與繁體開關、執行緒進階設定。
- XHR PUT 原始 File 上傳、獨立上傳進度、SSE 階段／逐段文字、估算 ETA、取消／錯誤狀態；只有 completed 顯示 100%。
- 渲染使用安全文字節點，避免來源檔名、逐字稿與詞彙變成 HTML；長稿增量呈現，快照補齊採分頁。
- 以伺服器狀態控制按鈕，頁面重新整理恢復活動任務；歷史切換不取消背景任務，終態後才允許刪除。
- TXT／MD 優先，SRT 次要；複製失敗提供可手動選取文字的回應，不自動送往其他 AI。
- start.bat 只使用已備妥 .venv；檢查環境、埠占用、服務就緒才開瀏覽器；README 說明首次準備、離線搬移、停止服務、保存位置及清理方式。

通過條件：短檔可由 UI 完整操作；重新整理、重開頁面與服務重啟後可回查結果；日常啟動不安裝／下載，所有頁面資產均來自本機。

#### 工作區清除（已實作，自動驗證完成，真人接受待確認）

- 在逐字稿工作區提供次要按鈕「清除工作區」，說明「只清空顯示，結果保留於本機歷史」。第一版僅在已有選取結果、結果已終止且沒有活動任務時啟用；上傳、載入、解碼、轉錄與取消中均反灰，保留明確原因。
- 清除後恢復空白預覽、預設標題、零進度及初始時間說明，清空本次錯誤／提示，停用複製與匯出。保留左側設定、選取的檔案、主題及歷史；不刪除結果、不取消工作、不釋放或竄改後端活動槽位。
- 釋放目前預覽 SSE、清空片段及待處理片段、遞增檢視世代，讓已發出的非同步回應與舊事件不能重新填回畫面。只清 DOM 不算完成。
- 以 sessionStorage 記住本分頁的空白意圖，重新整理仍維持空白；選取歷史或建立新任務後恢復正常預覽。儲存受阻時，本次清除仍可用，但重新整理可能依既有行為恢復最近任務。此狀態不保存逐字稿內容。
- 可逆的顯示操作不增加確認對話框；在空白區提示「工作區已清除，結果仍保留於本機歷史」。實際刪除仍使用歷史清單既有的確認流程，清除不宣稱擦除敏感資料或磁碟空間。
- 驗收：已完成／失敗／取消／中斷可清；活動任務與空白頁反灰；清除時未完成的查詢與事件不回填；歷史能重開；同分頁重新整理仍空白；新任務可顯示；不送刪除／取消請求，且深淺色與窄版皆可操作。未來如允許轉錄中清除，須另設持續可見的背景任務狀態與返回／取消入口。

### M5：真實錄音與交付驗收

- 相同短片段比較 small／medium、4／6／8 執行緒，固定其他參數，記錄版本、冷啟動／載入／轉錄／總耗時、峰值 RAM、電源及前景／背景狀態。
- 完整 60 分鐘真實 MP4 驗證最後內容與時間軸，峰值 RAM 初始目標低於 8 GiB，實測未達標須記錄處置，不直接宣稱符合。
- 分階段取消驗證目標 5 秒內子程序退出；父程序強制退出／視窗關閉後無孤兒推論，重啟後結果可恢復。
- 斷網並排除全域 FFmpeg 依賴跑 MP4；確認缺模型／tokenizer／VAD 時可理解地失敗。離線環境設定與 mock 網路測試不能取代實際斷網驗證。
- 人工核對術語、型號、數字、否定詞、決議，記錄可接受與待改善項目；AI 寫出的會議紀錄正確性由使用者另行確認。

交付時留下本機驗收報告，列明使用樣本代號及環境，不提交敏感逐字稿。分別報告程式、自動測試、真實模型／長檔、人工接受；沒有證據的項目維持未完成。

## 5. 驗證方式與進度規則

程式存在且環境備妥後，常規檢查使用：

```powershell
uv run --no-sync pytest
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
```

Windows 與真實模型測試依 M0 定義的標記分開執行並報告，記錄 pass／fail／skip 與原因。UI 與真實會議人工驗收不得由單元測試數量取代。

每個 todo 勾選代表該列交付條件已達成，附檔案或命令／結果佐證；階段只有在其通過條件滿足後才完成。只寫好程式但尚缺模型或樣本驗證時，分開標示狀態。本次純規劃文件只驗證連結、結構、ID 及規格覆蓋，不執行尚不存在的測試。

## 6. 風險與處理順序

| 風險 | 優先驗證位置 | 未通過時的處理 |
|---|---|---|
| Python／原生 DLL 不相容 | M0／M1 | 固定可用版本；必要的版本變動先同步 SPEC |
| 模型缺檔卻回退聯網 | M1 | 缺檔測試與斷網載入，未通過不可標記模型就緒 |
| Windows 取消／父程序退出留下工作 | M2 | 用阻塞測試程序先驗證，再接真實引擎 |
| 上傳取消與磁碟寫入競爭 | M3 | 在邊界測試中驗證終態、清理及位置釋放 |
| 重連漏字／重啟資料損壞 | M2／M3 | 磁碟作為結果來源、分頁補齊、去重及中斷恢復 |
| 長檔過慢、記憶體偏高或術語辨識差 | M5 | 以量測選擇模型與執行緒，不預承諾處理時間 |

接續工作：先執行 T60.1／T60.2，將 R01 文字問題轉成可回聽的樣本與比較基準；保留既有串流競爭、記憶體與人工驗收待辦。這次僅更新規劃，不表示已開始安裝或修改程式。

### M6：先釐清文字品質問題

- 固定 R01 原始輸出與參數，選 00:00～00:03、00:54～00:57、01:24～01:26 作初始候選，保存音訊來源與全檔時間偏移。內容與逐字稿只放本機，文件只記樣本代號及統計。
- 回聽並建立約 8 分鐘參考文字、術語／型號與否定／承諾語句標記；先分清錄音本身、辨識、後處理及匯出造成的問題。
- 用 raw_text／text 比較驗證繁體轉換副作用；測試較保守的策略，不以全域同音字替換代替辨識改善。
- 對重複區間回聽；增加必要的引擎診斷，逐項比較參數，不直接刪掉連續相同文字。保留原始結果，輸出另外的可疑區間標記。
- 已加入可選 mixed 分段語言偵測及前文開關；預設維持中文與前文開啟。以固定五分鐘合成 WAV、同一 turbo revision／CPU INT8／8 執行緒依序比較 baseline、multilingual、independent，不把單次耗時或合成測試當成真實會議品質接受。
- 建立可追溯的段落視圖，細片段不覆寫，避免跨說話者合併；分離未做時不得假設相鄰句子出自同一人。

通過條件：有可回查的人工基準、轉換回歸樣例、重複原因分類及段落來源對應；「4 字中位數／66.8% 短片段」只作診斷統計，不當錯誤率。

### M7：裝置選擇與模型實測

- 在白名單及離線準備流程加入 large-v3-turbo／large-v3；模型與結果按 revision／run 保存。舊 small 模型及既有記錄仍可使用，實測前不改預設。
- CPU small／medium 固定 INT8；有 RTX 2060 實機時，四種模型先固定 int8_float16、相同 beam／VAD／提示比較；FP16 另測，禁止用不同硬體的時間直接推估模型加速倍數。
- 既有 small／medium 已備妥，可先做比較；turbo 準備完成後追加 CPU INT8，GPU 再比較四模型。turbo 是主要速度／品質候選，large-v3 是品質優先對照；CPU 預設與 medium 是否保留由實測決定，不預設 medium 過時。
- 裝置 auto／cpu／cuda 與實際 compute_type 進入 metadata／UI。auto 開始前選定，明確 cuda 不可用時報錯；OOM／執行期錯誤保留結果，不默默降級模型或重跑。
- 先做套件／驅動／CUDA DLL 檢查，記錄 RAM／VRAM 峰值。ASR 與說話者模型依序載入及釋放；無 GPU 時仍可完成 CPU 驗收，GPU 項目明列待實機。

通過條件：同樣本比較可重現、關鍵字／否定／數字錯誤可量化、輸出版本不覆蓋；選定預設須有人工品質與耗時接受結果，不強制 large-v3。

### M8：pyannote 與發言時間對齊

- 優先獨立 pyannote Community-1，不先整合整套 WhisperX。在隔離環境驗證 Python／PyTorch／解碼相容性及資源，再決定正式可選依賴與鎖檔；不在運行中的 .venv 安裝。
- 由使用者自行接受模型條件，授權憑證只用於本機準備；驗證完整模型、授權資產與依賴可離線工作，缺檔不連網補抓。
- 先實作 CPU 分離、可選人數範圍、run_id／speaker turns。GPU 作選用裝置並分階段釋放顯存，不把「支援 GPU」當「6 GB 一定足夠」。
- 以較細時間資訊對齊多位發言者；保存原始重疊資料，歧義歸 unknown／待確認。若需要額外對齊引擎，先提出相容性與品質結果再選擇，不直接歸整段給單一人。
- 分離與轉錄各有狀態；分離取消／失敗仍可下載已完成文字。既有任務因媒體已清理，須重新選原音驗證後才能補跑，不要求重新辨識整份文字。
- 遷移新增可選欄位及附屬檔案，舊 schema 可讀、無分離資訊時顯示未執行；回滾保留原始文字，不覆蓋 v0.1.0 資料。

通過條件：人工標註短樣本的切換、重疊、未知可追溯；CPU 離線、取消與失敗復原成立。沒有標註不宣稱分離準確率；對齊若無法可靠切分，明確保留不確定。

### M9：人工姓名、試聽與可追責匯出

- 來源指紋驗證後按需試聽代表性短片段；維持完成後刪除上傳副本的原則，後續試聽重新選原音，不默默永久保存音檔。
- 每個 run 的說話者姓名表、個別片段人工歸屬與原始推定分開保存，可修改及還原；重跑不得沿用尚未重新確認的標籤姓名。
- TXT／MD 保留說話者、時間戳及來源細片段，未知／重疊／分離未完成明確標示。整理指示區分提案與承諾，說話者不等同待辦負責人；代詞與第三人稱指派需回查。
- 先以同一短樣本驗證 AI 輸入資料及人工修正，再跑長檔。分別記錄文字品質、歸屬、耗時／資源與實際會議紀錄可用性，保留 v0.1.0 未完成的驗收項目。

通過條件：使用者能試聽、命名、修正及回查；完整匯出不漏字或杜撰人名，既有結果相容。下一版版本號及交付 refs 待實作驗收後另定，本次不建立 commit／tag 或推送。
